# ADR-0002 — ORM والترحيلات: Drizzle بدل Prisma

**التاريخ:** 2026-11-11 · **الحالة:** مُعتمد ومُنفَّذ · **يعدّل:** قرار المرحلة 1 (Prisma + Prisma Migrate)

## السياق

خطة المرحلة 1 اختارت **Prisma** لطبقة البيانات. عند تنفيذ المرحلة 3 تبيّن أن محرّك Prisma الثنائي (schema engine / query engine) يُنزَّل وقت التشغيل من `binaries.prisma.sh`، وهذا النطاق محجوب في بيئة التنفيذ الحالية:

```
$ npx prisma -v
Error: request to https://binaries.prisma.sh/…/schema-engine.gz.sha256 failed
```

النتيجة: `prisma generate` و`prisma migrate` **غير قابلين للتنفيذ**، فلا مخطط ولا ترحيلات ولا عميل — أي أن الصفقة كلها (Prisma) غير قابلة للتحقق هنا. وتجدر الإشارة إلى أن هذا القيد بيئي، لكنه كشف اعتمادًا معماريًا حقيقيًا: طبقة البيانات لا يجب أن تعتمد على محرّك ثنائي يُنزَّل من شبكة خارجية في وقت البناء، خصوصًا في CI مغلق أو بيئة نشر مقيّدة.

## القرار

اعتماد **Drizzle ORM 0.45.4 + drizzle-kit 0.45.4 + node-postgres (pg 8)**:

- الترحيلات **SQL نصية** داخل المستودع (`drizzle/0000_init.sql`, `drizzle/0001_extensions_and_integrity.sql`)، تُقرأ وتُراجع سطرًا سطرًا، وتُطبَّق بأداة `drizzle-kit migrate` أو بأي مشغّل SQL آخر.
- مخطط TypeScript مقسّم بالمجال (`src/server/db/schema/*.ts`) — مصدر واحد للحقيقة يُولّد SQL ويُعطي أنواعًا كاملة (`$inferSelect`).
- `casing: 'snake_case'` في التوليد وفي وقت التشغيل، فيبقى TypeScript camelCase وSQL snake_case بلا تعيين يدوي.
- ما لا تستطيع drizzle-kit التعبير عنه (امتدادات، `plpgsql`، `TRIGGER`, `UUIDv7`, فهارس تعبيرية) مكتوب بيد في ترحيل 0001 مع تعليقات تشرح السبب.

## البدائل المرفوضة

| البديل | سبب الرفض |
|---|---|
| Prisma كما في الخطة | محرّك ثنائي محجوب → غير قابل للتشغيل/الاختبار في هذه البيئة |
| Kysely | كتابة SQL أفضل، لكن لا توليد ترحيلات ولا مخطط تعريفي موحّد للأنواع |
| TypeORM | ناضج لكن تجربة رقيقة مع TypeScript strict و`exactOptionalPropertyTypes`، ومزيد من «السحر» في وقت التشغيل |
| SQL خام فقط | مُتعِب مع 43 جدولًا، وتفقد الأنواع المشتقة التي تحمي المستودع |
| Prisma مع محرّك محلي مُثبّت مسبقًا | ممكن نظريًا، لكنه يجعل CI والنشر يعتمدان على تحميل ثنائيات خارجية — نفس المشكلة تتكرر في Vercel |

## النتائج (مقاسة)

- ✅ `drizzle-kit migrate` طبّق 213 عبارة SQL على Postgres 17 بنجاح.
- ✅ 43 جدولًا و22 نوعًا و25 فحصًا في `db:verify` — كلها خضراء.
- ✅ 32 اختبار تكامل نُفِّذت على محرّكين: PGlite داخل العملية، وPostgres عبر TCP بسائق `pg` الإنتاجي.
- ✅ حزمة الإنتاج: لا محرّك ثنائي، لا خطوة `postinstall` تُنزّل شبكة.
- ⚠️ التكلفة: لا «client» مولَّد بAPI كائنية (Prisma Client)؛ الكتابة أقرب إلى SQL، وهذا مقصود ويُقرأ بوضوح في المستودع.

## الأثر على المراحل اللاحقة

- المرحلة 4 (المصادقة): الاستعلامات تُكتب بـ Drizzle؛ لا يوجد `adapter` جاهز لـ Better Auth/Drizzle إلا عبر `drizzleAdapter` المدعوم، ويُتحقّق منه في حينه.
- المرحلة 5+ (الطلبات والسلة): تُستفاد من المعاملات (`db.transaction`) وقفل المخزون بـ `SELECT … FOR UPDATE`.
- أي عودة إلى Prisma مستقبلًا تعني إعادة كتابة المستودع وليس الصفحات — بفضل واجهة `CatalogRepository`.
