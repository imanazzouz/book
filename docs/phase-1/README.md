## 2. خلاصة القرارات الكبرى (باختصار شديد)

| القرار | الاختيار | لماذا في سطر |
|---|---|---|
| الشكل المعماري | **Modular Monolith** داخل Next.js مع 5 طبقات مفصولة | سرعة إطلاق + فصل منطق الأعمال عن الواجهات دون تعقيد الخدمات المصغّرة |
| الإطار | **Next.js 16.4.6 + React 19.3.1 + TS 7 strict** | RSC/SEO للسوق، تقليل JS، نشر Vercel |
| ORM | **Prisma 7.10.1** + SQL خام للحالات الحرجة | Migrations ناضجة وعلاقات مقروءة، مع تحكم كامل عند الحاجة |
| Auth | **Better Auth 1.7.21** — Google OIDC + **Email OTP فقط** (بلا كلمات مرور) | يطابق متطلب OTP 6 أرقام والجلسات القابلة للإبطال، ويحذف مخاطر كلمات المرور |
| الصلاحيات | **RBAC بأكواد صلاحيات في DB** (`user_roles` → `role_permissions`) | يسمح بمشرفين بصلاحيات محدودة لاحقًا دون تعديل الكود |
| المال | **NUMERIC(12,2) + Decimal** ولغة DZD | لا `float` في الأموال إطلاقًا |
| الطلبات | `orders` → `seller_orders` لكل متجر | كل مزارع يدير طلبه فقط، بلا خلط مسؤوليات |
| المخزون | **خفض ذرّي شرطي** داخل Transaction | منع Overselling بنيويًا والقيد `CHECK (>=0)` كحاجز أخير |
| الدفع | **COD فقط** مع كيان `payments` جاهز | لا بوابة دفع وهمية |
| الصور | **فقط Vercel Blob**، وممنوع أي صورة AI أو كائن حيّ | التزام صريح بقيدك |

## 3. ما لم نفعله في هذه المرحلة (وهذا مقصود)

- لم نُنشئ `package.json` ولا أي صفحة، التزامًا بمطلبك «لا تبدأ بكتابة المشروع كاملًا قبل عرض الخطة».
- لم نضع أي بيانات منتجات/مزارعين/طلبات/تقييمات.
- لم ندّعِ أي اختبار أمني أو أداء — كل الاختبارات تبدأ من المرحلة 2، وستُنشر نتائجها الفعلية.
